# Axx 0.20.19 — Progressive custom speech

Custom Axx voices now send PCM chunks to Web Audio as they are generated. The
reader can play the first audio while the rest of the phrase is still being
synthesized, and prepare the next phrase while the preceding audio plays.

- Persistent MOSS worker, cooperative cancellation and reusable audio output.
- Model preparation at startup and reference preparation on voice selection.
- Private reference-code cache invalidated when the source sample or codec changes.
- Only required ONNX sessions are loaded; idle thread pools no longer spin.
- Pause/resume, ordered chunks, bounded buffers and explicit custom-voice errors.
- No silent substitution of a selected custom voice with a Windows voice.

On the development PC (Intel i7-1255U, CPU inference), eight prepared-voice tests
covering Alba, Nova, Aura and Titán in Spanish and English produced their first
PCM chunk in **359–391 ms** with four inference threads. Audio generation was faster than playback for these
test phrases. This is first PCM latency at the service, not total chat latency or
a guarantee for other machines. Initial model preparation still takes roughly
10–14 seconds; an uncached reference takes another 2–4 seconds. Preparation runs
in the background and the UI displays its state.

The final installed Windows build was then tested through its native WebView,
authenticated backend and Web Audio output:

| Voice | Spanish playback start | English playback start | Buffer underruns |
| --- | ---: | ---: | ---: |
| Axx Alba | 1041 ms | 669 ms | 0 |
| Axx Nova | 1008 ms | 694 ms | 0 |
| Axx Aura | 997 ms | 669 ms | 0 |
| Axx Titán | 695 ms | 654 ms | 0 |

All eight readings reached the ended state. Cancelling an active reading and
starting another took 737 ms to playback, with zero underruns. These are native
audio-clock observations; no external speaker/microphone loopback was recorded.
Preparation now exercises the actual synthesis/PCM path before reporting ready.
PCM delivery uses a waiting backend request rather than browser polling timers.

Validation: 42 backend tests, the focused stream/server regression suite after the
final transport adjustment, 18 desktop interface checks, nine chat checks and
Web Audio progressive playback, pause/resume, ordering and cancellation checks.

Both languages are supported by the [upstream model](https://github.com/OpenMOSS/MOSS-TTS-Nano#supported-languages).
The four voices still require the user's local MOSS installation and reference
audio. Cross-language pronunciation and voice similarity depend on the supplied
reference; local tiny-model ASR checks do not certify perceptual quality.

The installer is unsigned. Existing phone permissions and Android installation
requirements remain unchanged. No user audio or model weights are published.
