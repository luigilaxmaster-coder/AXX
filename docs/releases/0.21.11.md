# Axx 0.21.11 — CMD propuesto y controles de ventanas

## Cambios

- Una petición que menciona CMD o terminal permite al modelo proponer un comando de CMD. Axx muestra el script completo y espera aprobación antes de ejecutarlo. PowerShell no se ofrece al planificador.
- Los scripts propuestos no se guardan como habilidades ni se repiten automáticamente. La salida y el código de retorno quedan en el recibo; éxito del proceso no confirma por sí solo el objetivo del usuario.
- «Pulsa [botón] en [aplicación]», «escribe en [aplicación]: [texto]», «inspecciona controles de [aplicación]», «lee la ventana de [aplicación]» y «enfoca [aplicación]» usan una ventana visible única observada por Windows. Escribir y pulsar requieren aprobación y revalidación del control.
- Si el modo ChatGPT del chat no está conectado al planificador, Axx indica que debe elegirse un modelo de acciones configurado en lugar de simular ejecución.

## Alcance y verificación

- Las órdenes de ventana dependen de los controles que cada aplicación exponga a Windows UI Automation. Una ventana ambigua o sin control único no se acciona.
- CMD se ejecuta en segundo plano desde Axx/artifacts con límite de 30 segundos; no abre una consola visible.
- La prueba con micrófono físico, las acciones reales dentro de cada aplicación y la latencia de voz requieren validación en el equipo instalado. Ningún catálogo equivale a cobertura total de comandos.
