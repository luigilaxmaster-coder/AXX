## 1. Executive Summary

This investigation provides an exhaustive technical analysis of the Python backend service, its inference failover pipeline, the command/tool execution subsystem, and the authentication and isolation guardrails protecting user files.

Key findings:
1. **Authentication is Ephemeral and Process-Bound**: Requests to the loopback server (`127.0.0.1:<port>`) are authenticated via a private Bearer token generated by Tauri at runtime (`Uuid + Uuid`, 64 hex characters) and transmitted through the environment variable `AXX_HOST_TOKEN`. It is **never** written to `state.db`. Furthermore, browser-origin requests are unconditionally rejected via `Origin` header presence checks (`server.py:97`).
2. **Local Ollama (Port 11434) is Completely Blocked in the Backend Router**: While the frontend (`Axx.html:6355`) attempts direct `fetch()` to `http://127.0.0.1:11434`, the Python backend's `Router` in `router.py:204` hard-rejects any provider URL that is not `https://`, and `http_transport` insists on resolving a non-empty `api_key_env`. Consequently, local Ollama cannot currently be registered or routed through `InferenceAdapter` as a local offline model.
3. **The `USE_COMMAND_POLICY` Barrier (Line 474)**: The legacy endpoint `POST /axx-api/actions/execute` explicitly forbids any tool with side effects (`file_artifact_writer`, `blender_render_fixture`), returning HTTP 403 `USE_COMMAND_POLICY`. The frontend (`Axx.html:18817`) calls `actions/execute` directly, which causes immediate HTTP 403 errors unless `1.AXX/scripts/command-library.js` successfully monkey-patches `Axx.desktop.execute`.
4. **Absolute File System Isolation**: File creation via `file_artifact_writer` is strictly verified through triple-layer validation (`commands.py:220`, `executor.py:120`, `tools.py:109`). Destination paths are strictly confined to `%LOCALAPPDATA%\Axx\artifacts` using relative resolution, exclusive creation mode (`xb`), and symlink/junction rejection. The user's `Desktop` and `Documents` directories are completely shielded and cannot be written to or modified by the backend.
5. **Tool Registry Composition**: `tools.py` defines exactly 4 tools: `file_artifact_writer`, `system_telemetry`, `process_state_inspector`, and `blender_render_fixture`. Math (`safeCalculate`) is executed purely client-side in JavaScript, and Timer is split between client-side DOM ticks and a stubbed Tauri Rust command (`set_timer`).

### 2.2 Security & Authentication Lifecycle

The authentication mechanism is implemented in `AxxBridgeHandler._authorized()` (`server.py:91-110`):

1. **Host Header Validation**:
   ```python
   expected_hosts = {f'127.0.0.1:{self.server.server_port}', f'localhost:{self.server.server_port}'}
   if self.headers.get('Host') not in expected_hosts:
       self._send_json(403, {'error': {'code': 'FORBIDDEN', 'message': 'Invalid loopback host'}})
       return False
   ```
   Rejects any request arriving with DNS rebinding or external IP headers.
2. **Origin Header Suppression**:
   ```python
   if self.headers.get('Origin'):
       self._send_json(403, {'error': {'code': 'FORBIDDEN', 'message': 'Use the native host bridge'}})
       return False
   ```
   If a standard browser window (or third-party malicious website) attempts a `fetch()` or `XMLHttpRequest` to the local port, browsers automatically attach the `Origin` header. The backend immediately blocks this with HTTP 403 `FORBIDDEN`.
3. **Bearer Token Validation**:
   - Tauri v2 (`src-tauri/src/lib.rs:586-614`) spawns the Python backend in a Windows Job Object:
     ```rust
     let token = format!("{}{}", uuid::Uuid::new_v4().simple(), uuid::Uuid::new_v4().simple());
     command.env("AXX_HOST_TOKEN", &token);
     ```
   - Python reads `os.environ.get('AXX_HOST_TOKEN')` in `ThreadedHTTPServer.__init__` (`server.py:53`).
   - Every request forwarded by Tauri's Rust command `backend_request` uses `reqwest::blocking::Client` without an `Origin` header and attaches:
     `Authorization: Bearer <token>`.
   - `_authorized()` executes a constant-time comparison:
     ```python
     if not secrets.compare_digest(value, 'Bearer ' + self.server.host_token):
         self._send_json(401, {'error': {'code': 'UNAUTHORIZED', 'message': 'Native host authentication required'}})
         return False
     ```
   - **Conclusion on Token Storage**: The token is **never persisted in `state.db`**; it is purely ephemeral, held in RAM during the active process lifecycle, and regenerates on each application launch.

## 3. Inference Engine & Ollama Port 11434 Lifecycle

### 3.1 Invocation Pipeline of `InferenceAdapter`

When `POST /axx-api/chat` is invoked:
1. `server.py:278` validates allowed keys: `{'model', 'stream', 'axx_task', 'messages', 'temperature', 'max_tokens', 'tools', 'request_id', 'conversation_id', 'deadline_ms', 'sensitivity', 'provider', 'allow_fallback', 'mode'}`.
2. Envelopes the payload and passes it to `self.adapter.route(envelope)` (`backend/inference/adapter.py:202`).
3. `InferenceAdapter.route` validates parameters and bounds:
   - Request ID (1-128 chars), Conversation ID (1-128 chars), Wall deadline (1 to 70,000 ms, default 70s).
   - Sensitivity: must be `'public'` or `'approved_sensitive'`.
   - Concurrency limit: max 2 active requests; rejects excess with HTTP 409 `BUSY`.
4. Process Isolation Boundary (`_worker_result` at `adapter.py:121`):
   - Rather than executing inference in the server thread, it launches an isolated worker process:
     `python -m backend.server --router-worker --state <state.db>`
   - The worker runs `worker_main()` (`adapter.py:26`) inside a Windows Job Object.
   - Bounded communication: input JSON capped at 3 MiB (`MAX_WORKER_INPUT`), output JSON capped at 8 MiB (`MAX_WORKER_OUTPUT`).
5. Inside the worker, `Router.chat()` (`backend/inference/router.py:483`) executes sequential failover over the configured providers list.

### 3.2 Sequential Failover & Cooldown Logic in `Router`

`Router` provides comprehensive failover:
- Checks provider eligibility: `enabled == True`, `allow_paid == False` (only free models permitted), capabilities match (e.g., `tools` or `vision`), and `api_key_env` resolved.
- SQLite Atomic Quotas (`router.py:286-325`):
  - Tracks daily attempts in table `usage (name, day, attempts, quota_scope_id)`.
  - Atomically increments attempts in `usage` and `scope_usage`. If quota is exceeded, skips provider.
- HTTP Request Execution (`http_transport` at `router.py:88`):
  - Uses `urllib.request` with `NoRedirect` handler.
  - Timeout is calculated as `min(self.timeout, remaining_global_deadline)`.
- Upstream Error Handling:
  - HTTP 429: extracts `Retry-After` header (capped at 86400s) and inserts into table `cooldown` (`router.py:332`).
  - HTTP 500, 502, 503, 504: applies 30s cooldown.
  - HTTP 403 / Content Filter: raises `PolicyBlocked` immediately (no retry, halts failover).
  - Tries next provider up to `max_attempts` (default 3). If all fail, raises `Exhausted` (`code='NO_PROVIDER_AVAILABLE'`).

## 4. Command Engine & Execution Policy (`backend/commands.py` & `backend/actions/tools.py`)

### 4.1 The Two-Phase Command Workflow

`backend/commands.py` (`CommandService`) implements a closed, typed boundary separating untrusted model outputs or user strings from the actual system tools:

```
[User Input / Voice]
         │
         ▼
POST /axx-api/commands/resolve
  ├── Regex: /comando <id> {json}
  └── Aliases: 'estado del sistema', 'estado de axx'
         │
         ▼
POST /axx-api/commands/prepare
  ├── Schema Validation (types, bounds, maxBytes)
  ├── Preconditions Verification (filesystem check, target cannot exist)
  └── Persist to SQLite `command_runs`:
        ├── Risk == 'read'  ──> state: 'prepared'
        └── Risk != 'read'  ──> state: 'awaiting_approval' (TTL: 300s)
         │
         ▼
[Frontend UI Inspection & Approval Dialog]
         │
         ▼
POST /axx-api/commands/execute
  ├── Acquire `execution_gate` (single-execution lock)
  ├── Check expiration (expires_at > now)
  ├── Verify `approved == True` if requires_approval
  ├── Re-validate inputs & filesystem preconditions
  ├── Transition state: 'running'
  ├── Invoke `ActionExecutor.execute_action()`
  ├── Postconditions Verification (hash, length, active PID)
  └── Update SQLite `command_runs`:
        └── state: 'succeeded' | 'failed' | 'unknown'
```

### 4.2 The `USE_COMMAND_POLICY` Check at `server.py:474`

In `backend/server.py`:

**Policy Rationale & Specification**:
- Direct action execution via `/axx-api/actions/execute` is strictly restricted to read-only queries with zero system side effects (`system_telemetry` and `process_state_inspector`).
- Any tool that can modify the filesystem (`file_artifact_writer`) or spawn external heavy executables (`blender_render_fixture`) is blocked with HTTP 403 `USE_COMMAND_POLICY`.
- **How Endpoints Must Be Invoked**:
  1. For safe reads: Client may invoke `POST /axx-api/actions/execute` directly, OR use `POST /axx-api/commands/prepare` -> `POST /axx-api/commands/execute`.
  2. For writes or external executions: Client **must** invoke `POST /axx-api/commands/prepare` to generate an `operation_id`, present the preview/diff to the user, and then invoke `POST /axx-api/commands/execute` with `{ "operation_id": "<id>", "approved": true }`.

### 4.3 Tool Catalogue & Registry Breakdown (`backend/actions/tools.py`)

## 5. Architectural Flaws, Discrepancies & Root Causes

Through our investigation, we have isolated five core defects causing command and chat failures:

### Defect 1: Race Condition in Frontend Desktop Command Hooking
- **Observation**: In `1.AXX/Axx.html:18817`, `DesktopRuntime.execute()` calls `POST /axx-api/actions/execute` directly.
- **Root Cause**: `1.AXX/scripts/command-library.js` contains `connectExistingActions()` (`line 56`):
  `if (!Axx.desktop) return;`
  `Axx.desktop.execute = async (toolName, inputs) => { ... await this.prepare(...) };`
  Because `Axx.desktop` (`DesktopRuntime`) is instantiated later in `Axx.html` (line 18901), when `command-library.js` executes, `Axx.desktop` is undefined!
  The hook silently aborts (`return`), leaving the raw `Axx.desktop.execute` active. When the user attempts any action in the Desktop panel, it hits `/axx-api/actions/execute` and crashes with HTTP 403 `USE_COMMAND_POLICY`.

### Defect 2: Local Ollama Blocked by Strict HTTPS Requirement in Router
- **Observation**: The user machine has Ollama running on port 11434 with `llama3.1:8b`. The backend cannot use it.
- **Root Cause**: In `backend/inference/router.py:204`, `Router._validate_config()` enforces:
  `if u.scheme != 'https' ... raise ValueError("base_url must be HTTPS without credentials/query/fragment")`.
  Additionally, line 94 unconditionally looks up `os.environ[provider['api_key_env']]`.
  This prevents adding local Ollama (`http://127.0.0.1:11434/v1`) as a provider in `providers.json`.

### Defect 3: `commands.py` Concurrency Gate Returns HTTP 400 Instead of 409
- **Observation**: When two command requests arrive in rapid succession, the backend responds with HTTP 400 `INVALID_REQUEST`.
- **Root Cause**: In `backend/commands.py:281`:
  `if not self.execution_gate.acquire(blocking=False): raise ValueError('BUSY: hay una operación de catálogo en curso')`.
  Raising `ValueError` causes `server.py:603` to catch it under `(ValueError, TypeError, ActionExecutionError)` and return HTTP 400. It should raise a custom `BusyError` that maps to HTTP 409 `BUSY`.

### Defect 4: Frontend Chat Crashes on Upstream Tool Calls
- **Observation**: In `1.AXX/Axx.html:6416`:
  ```javascript
  const text = data.choices?.[0]?.message?.content, reason = data.choices?.[0]?.finish_reason;
  if (typeof text !== 'string' || !text.trim() || typeof reason !== 'string')
      throw new Error('El proveedor no confirmó una respuesta de texto válida.');
  ```
- **Root Cause**: When an LLM model issues a tool call, `message.content` is typically `null` or `""` and `finish_reason` is `"tool_calls"`. `Axx.html` treats this as a fatal failure and throws an error instead of executing the tool or presenting the tool call.

### Defect 5: Configuration Divergence in `save-key`
- **Observation**: In `backend/server.py:372`:
  ```python
  cfg_path = getattr(self, 'config_path', None)
  if not cfg_path or not Path(cfg_path).exists():
      cfg_path = root_dir / 'providers.json'
  ```
- **Root Cause**: If `self.config_path` is not initialized or points to a non-existent path, it writes `providers.json` into the root repository workspace instead of `%LOCALAPPDATA%\Axx\providers.json`, causing configuration split-brain.

## 6. Actionable Fix Strategy Formulation

To resolve Milestone 3 issues completely without destabilizing the system, the following concrete modifications are recommended for implementation:

### 6.1 Recommendations for `backend/inference/router.py` & `providers.json`
1. **Permit Local Loopback HTTP Providers**:
   Update `router.py:203` to allow `http://` specifically for loopback hosts:
   ```python
   # Allow HTTPS for remote providers, and HTTP strictly for local loopback (Ollama / LocalAI)
   is_loopback = u.hostname in ('127.0.0.1', 'localhost', '::1')
   if (u.scheme == 'http' and not is_loopback) or (u.scheme not in ('http', 'https')) or not u.hostname ...:
       raise ValueError("base_url must be HTTPS or local loopback HTTP")
   ```
2. **Optional API Key for Local Providers**:
   In `http_transport` (`router.py:94`):
   ```python
   headers = {'Content-Type': 'application/json'}
   if provider.get('api_key_env') and os.environ.get(provider['api_key_env']):
       headers['Authorization'] = 'Bearer ' + os.environ[provider['api_key_env']]
   ```
3. **Register `ollama-local` in `providers.json`**:
   Add a local provider entry with high priority:
   ```json
   {
     "name": "ollama-local",
     "base_url": "http://127.0.0.1:11434/v1",
     "model": "llama3.1:8b",
     "api_key_env": "OLLAMA_API_KEY",
     "enabled": true,
     "free_confirmed": true,
     "daily_attempt_limit": 5000,
     "max_output_tokens": 2048,
     "quota_scope_id": "local-ollama",
     "capabilities": ["text", "tools"]
   }
   ```
   With this, when Ollama is running, chat inference is instant, local, offline, and free. If Ollama is offline, the router catches connection refused and falls back cleanly.

### 6.2 Recommendations for `backend/commands.py`
1. **Introduce Explicit `CommandBusyError`**:
   Define `class CommandBusyError(Exception): pass`.
   In `execute()`:
   ```python
   if not self.execution_gate.acquire(blocking=False):
       raise CommandBusyError('Hay una operación de catálogo en curso')
   ```
2. **Handle `CommandBusyError` in `server.py`**:
   Map `CommandBusyError` to HTTP 409 `BUSY`:
   ```python
   except CommandBusyError as exc:
       self._send_json(409, {'error': {'code': 'BUSY', 'message': str(exc)}})
   ```

### 6.3 Recommendations for `backend/server.py`
1. **Unify `config_path` Persistence**:
   Ensure `cfg_path` always resolves to `resolve_app_paths()[0]` (`%LOCALAPPDATA%\Axx\providers.json`), never modifying the repository root.
2. **Clean JSON Error Responses**:
   Ensure all exceptions in `do_POST` and `do_GET` consistently return a structured JSON body with `error.code` and `error.message`, avoiding generic 500 crashes.

### 6.4 Recommendations for Frontend Integration (`1.AXX/scripts/command-library.js` & `Axx.html`)
1. **Fix Hook Timing**:
   In `command-library.js`:
   Replace `if (!Axx.desktop) return;` with a resilient getter/setter or polling check that guarantees `Axx.desktop.execute` is hooked as soon as `DesktopRuntime` is initialized.
2. **Handle Non-Text Tool Call Responses Gracefully**:
   In `Axx.html:6416`, check if `choices[0].message.tool_calls` is present. If so, format a readable summary in chat (e.g. `🔧 Solicitud de comando: <tool_name>`) rather than crashing with "El proveedor no confirmó una respuesta de texto válida".
