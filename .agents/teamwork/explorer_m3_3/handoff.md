## 1. Observation

1. **Authentication Mechanism (`backend/server.py:53, 91-110`)**:
   `self.host_token = os.environ.get('AXX_HOST_TOKEN') or secrets.token_hex(32)`.
   In `_authorized()`, lines 97-99 reject any request with an `Origin` header (`HTTP 403 FORBIDDEN: Use the native host bridge`).
   Line 101 validates `Authorization` using `secrets.compare_digest(value, 'Bearer ' + self.server.host_token)`.
   The token is generated by Tauri v2 (`src-tauri/src/lib.rs:586-614`) at launch as a 64-character hex string and passed via environment variable `AXX_HOST_TOKEN`. The token is **never persisted in `state.db`**; it exists solely in memory during the process lifecycle.
2. **Router Rejects HTTP Local Endpoints (`backend/inference/router.py:203-205`)**:
   ```python
   u = urllib.parse.urlsplit(p['base_url'])
   if u.scheme != 'https' or not u.hostname or u.username or u.password or u.query or u.fragment:
       raise ValueError("base_url must be HTTPS without credentials/query/fragment")
   ```
   And line 94: `'Authorization': 'Bearer ' + os.environ[provider['api_key_env']]`.
   Local Ollama runs on `http://127.0.0.1:11434`, but `Router` rejects any URL with `scheme != 'https'`, preventing local Ollama from functioning as a backend provider in `providers.json`.
3. **Frontend Direct Ollama Path (`1.AXX/Axx.html:6355-6433`)**:
   When `p.provider === 'ollama'`, `BrainClient` sends direct browser requests to `http://127.0.0.1:11434/api/tags` and `http://127.0.0.1:11434/api/chat`. If Ollama is online, it succeeds without going through the backend. If Ollama is offline, `fetch()` throws `TypeError: Failed to fetch`, which is caught and marked as connection failure.
4. **`USE_COMMAND_POLICY` Gating (`backend/server.py:474-477`)**:
   ```python
   if body.get('tool_name') not in ('system_telemetry', 'process_state_inspector'):
       self._send_json(403, {'error': {'code': 'USE_COMMAND_POLICY',
           'message': 'Prepara y aprueba este comando en la biblioteca; la ruta antigua no autoriza efectos.'}})
       return
   ```
   Direct calls to `/axx-api/actions/execute` with any tool other than `system_telemetry` or `process_state_inspector` fail with HTTP 403.
5. **Frontend Hook Race Condition (`1.AXX/Axx.html:18817` vs `1.AXX/scripts/command-library.js:56`)**:
   `Axx.html:18817` has `DesktopRuntime.execute` invoking `POST /axx-api/actions/execute`. In `command-library.js:56`, `connectExistingActions()` has `if (!Axx.desktop) return;`. Because `Axx.desktop` is instantiated at line 18901 (after `command-library.js` evaluates), the monkey-patch aborts, leaving `Axx.desktop.execute` calling `/axx-api/actions/execute`, triggering HTTP 403 `USE_COMMAND_POLICY`.
6. **File Isolation & Protection (`backend/commands.py:216-222`, `backend/actions/executor.py:112-125`, `backend/actions/tools.py:108-138`)**:
   - `commands.py:216` rejects absolute paths, drive letters, `..`, and reserved names; verifies `target.is_relative_to(self.executor.workspace_root)`.
   - `executor.py:120` verifies `candidate.is_relative_to(self.workspace_root)`.
   - `tools.py:137` opens files exclusively with `target.open('xb')`.
   - Workspace root is instantiated in `server.py:659` as `state_dir / 'artifacts'` (`%LOCALAPPDATA%\Axx\artifacts`). User Desktop and Documents are strictly protected from modification.
7. **Tool Registry Contents (`backend/actions/tools.py:322-327`)**:
   Only 4 tools exist in `TOOL_REGISTRY`: `file_artifact_writer`, `system_telemetry`, `process_state_inspector`, and `blender_render_fixture` (disabled). Math is evaluated client-side in JS (`Axx.safeCalculate`), and Timer is split between client-side ticks and a stubbed Tauri command (`set_timer`).

## 2. Logic Chain

1. From Observation 1, client-side browser requests are rejected via `Origin` checks, and IPC calls require the ephemeral Bearer token from Tauri. The authentication is secure and process-bound, not stored in `state.db`.
2. From Observation 2 and 3, when the user chooses `provider: 'bridge'` (the backend router), the router only knows `openrouter-free` from `providers.json`. If `OPENROUTER_API_KEY` is not set, `Router.chat()` exhausts all providers and returns HTTP 502 `NO_PROVIDER_AVAILABLE`. Although Ollama is running locally on port 11434 with `llama3.1:8b`, the backend router cannot use it because of the strict `https` and mandatory API key environment variable requirements.
3. From Observation 4 and 5, any action attempted from the Desktop UI that writes files triggers an unhandled HTTP 403 `USE_COMMAND_POLICY` because `DesktopRuntime.execute` attempts legacy execution rather than the two-phase `commands/prepare` -> `commands/execute` flow, caused by the script load-order race condition.
4. From Observation 6, file safety is mathematically constrained: all write operations require relative paths resolving strictly within `%LOCALAPPDATA%\Axx\artifacts`, preventing any unauthorized writes to the user's Desktop or Documents folders.
5. From Observation 7, tool execution for non-telemetry actions requires proper registration in `ADAPTERS` (`commands.py:25`) and two-phase preparation before invocation.

## 3. Caveats

- We did not execute live modifications to the codebase (strict read-only explorer discipline).
- We did not kill or start local Ollama processes during this audit.

## 4. Conclusion

The Python backend is architecturally sound and possesses high-quality security boundaries (ephemeral token auth, bounded JSON parsers, failover routing, and directory-jailed file writes).
However, three integration bugs completely disrupt user interaction:
1. **Ollama Routing Gap**: `router.py` must be updated to permit `http://127.0.0.1:*` and `http://localhost:*` without mandatory API keys, and `ollama-local` should be registered in `providers.json`.
2. **Frontend-Backend Command Policy Desynchronization**: `command-library.js` must safely hook `Axx.desktop.execute` (avoiding the undefined `Axx.desktop` race condition) so that file creation uses `/axx-api/commands/prepare` and `/axx-api/commands/execute` instead of hitting the forbidden legacy route `/axx-api/actions/execute`.
3. **Frontend Chat Crash on Tool Calls**: `Axx.html:6416` must handle responses containing `tool_calls` gracefully rather than throwing an unhandled exception when `message.content` is null.
